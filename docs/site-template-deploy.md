# Site template deploy contract

What every site generated by the pipeline must contain so that
**auto-deploy on push** and **dashboard edits via `/custom-prompt`** work
out of the box. The contract is enforced by `fluxgateseo/elite-astro-template`;
new sites inherit it on Stage 5a fork. `patches/template-elite-fixes.patch`
brings the template up to this contract — apply it once to the template
and every future site is correct by construction.

## Required files in the template

| File | Purpose |
|---|---|
| `.nvmrc` | Pins Node to a version compatible with `package.json` engines (currently `22.12.0`). `actions/setup-node` reads it. |
| `.npmrc` | `legacy-peer-deps=true`. Resolves the `astro@^6` ↔ `@astrojs/tailwind@^6.0.2` peer conflict so `npm ci` succeeds. |
| `.github/workflows/deploy.yml` | GHA: `npm ci` → `npm run build` → `npx tsc --noEmit` → `cloudflare/wrangler-action@v3` `pages deploy dist`. **Uses npm** (matches the `package-lock.json` shipped by the template); the previous `pnpm install --frozen-lockfile` step failed because no `pnpm-lock.yaml` is committed. Deploy step gated on `vars.PAGES_PROJECT_NAME != ''` so Stage 5a's initial commit doesn't try to deploy before Stage 6c has populated the variable. |
| `src/layouts/BaseLayout.astro` | Maps `--color-fg / --color-muted / --color-divider` from the palette so text contrast is correct regardless of the chosen palette. |
| `src/layouts/ArticleLayout.astro` | Renders "Articoli correlati" at the bottom of every article: same-category articles, excluding self, top 3 by date. Uses `getCollection("articoli")`. |
| `src/pages/galleria.astro` | Reads `src/data/gallery.json` (not the old hardcoded empty array placeholder) so the standalone `/galleria` page renders the same set the homepage `PhotoMosaic` shows. |

## Pipeline Stage 6c — repo secrets/vars (existing)

`andreabbo/elite-pipeline-workflow` must set on each new `site-<slug>`:

- Secret `CLOUDFLARE_API_TOKEN` (sealed_box-encrypted, account-scoped — `tweetnacl` + `blakejs`).
- Variable `CLOUDFLARE_ACCOUNT_ID`.
- Variable `PAGES_PROJECT_NAME` (= `site-<slug>`).

The deploy.yml step is gated on the variable so the order
Stage 5a-create → Stage 6c-secrets → Stage 5b-overlay-commit is what
actually triggers the first real deploy.

## Dashboard edits — `/custom-prompt`

Already wired end-to-end (see `docs/custom-prompt.md`): each `live` row
in `app.innotofuture.com/sites` has a `prompt ↗` action that POSTs to
`elite-pipeline-workflow`'s `/custom-prompt`. The worker calls Claude
Opus, commits to `main` via a multi-blob commit, and the same
`deploy.yml` above auto-deploys the change. No per-site setup needed
beyond the template patch + Stage 6c.

## Sitemap / canonical base URL  *(contract — regression 2026-05-29)*

**Symptom.** `https://<domain>/sitemap.xml` resolves but every `<loc>`
points at `https://demo.example/sitemap-0.xml` instead of the real
domain (observed on `modoristorante.it`).

**Root cause.** `@astrojs/sitemap` derives every URL from Astro's `site`
option. Stage 5b writes a per-site `astro.config.site.mjs` (`siteUrl`
helper), and `astro.config.mjs` is supposed to consume it as
`site: siteUrl`. The build instead fell back to the template placeholder
`https://demo.example` — either `astro.config.mjs` never imported
`siteUrl`, or Stage 5b emitted `astro.config.site.mjs` with the
placeholder still in place. The same `site` value drives canonical
`<link rel="canonical">` and the `robots.txt` sitemap reference, so the
blast radius is every generated site, not just the sitemap.

**Contract (enforced by the template + worker):**

- `astro.config.mjs` MUST set `site` from `astro.config.site.mjs`'s
  `siteUrl` — never a hardcoded literal. The template default, if any,
  must be obviously invalid (e.g. throw at build if unset) rather than a
  plausible-looking `demo.example` that ships silently.
- Stage 5b's `renderSiteConfig`/overlay MUST write
  `siteUrl = "https://<domain>"` (the brief's domain, TLS, no trailing
  slash) into `astro.config.site.mjs`. `demo.example` must never reach a
  committed `astro.config.site.mjs`.
- Stage 7 fails the build if `/sitemap.xml` contains `demo.example` or
  any `<loc>` not under `https://<domain>` (see `docs/pipeline-stages.md`).

**Backfill for already-live sites (e.g. `site-modoristorante`).** Fix
`astro.config.site.mjs` (and/or `astro.config.mjs`) in the site repo so
`site` is `https://<domain>`, commit, push — the GHA deploy rebuilds and
the corrected sitemap/canonicals go live. Re-submit the URL to Search
Console afterwards.

## Verifying a new site at Stage 7

`docs/pipeline-stages.md` Stage 7 already smoke-tests `/`, `/sitemap.xml`,
`/robots.txt`. Add to the same step (cheap):

- `/galleria` returns 2xx and is non-empty (no `appariranno qui` string)
- A random article page contains ≥ 1 link to `/blog/` and the literal
  `it.wikipedia.org` or `nasa.gov`

Catches the two regressions we hit on the May-2026 sites (empty gallery,
no interlink/authoritative link) before the site is marked `live`.

## Backfill for sites already created before this fix

For sites already in `fluxgateseo/site-<slug>` that pre-date the
contract: `git apply patches/template-elite-fixes.patch` on the site
repo, commit, push — the next push will trigger the now-working GHA
deploy. Already done in this session for `site-agilescienceapp` and
`site-modoristorante` (delivered as squashed `*-FINAL.patch` + `dist.zip`
fallback).
